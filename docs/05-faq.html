Editing and publishing

How do I switch from another Jekyll theme?

Follow the migration guide and checklist to adapt your configuration, layouts and integrations. If the build or design is unexpected, check the common migration problems.

How do I change my site’s name or author?

Follow Change your site’s name and author to edit the existing settings, match the home-page heading and verify publication. The complete field reference remains available for option lookup.

How do I add a new article or page?

For an article, create _posts/YYYY-MM-DD-title.md with a real date and the settings block at the top. For a standalone page, use _pages/ in the starter and add its address to your menu. Follow the complete examples in Create a post and Create a page.

Why can I not see my changes?

Follow Find changes missing from your website to check the saved commit, publishing run, website address and post date. For a configuration parse error, use Fix a YAML configuration error.

Why is my photograph missing?

Check that the file was uploaded and saved, and that its filename matches the link exactly, including uppercase and lowercase letters. Use the image example in Add an image, which handles repository paths. After publishing, check the article again rather than the GitHub file preview.

How do I change the colors or design?

Choose a skin from the previews, then change the existing chulapa-skin.skin entry in _config.yml. See Skins. Changing a preview in your browser does not save the design to your own website.

…start with Markdown?

We’ve got you covered.

See the Markdown cheatsheet and kramdown reference. The sample configuration uses kramdown with its GFM parser; accepted syntax depends on your Markdown configuration.

For a complete file with its settings block and text, see Create a post.

…add custom HTML, analytics, CSS or JavaScript to every page?

Follow Add custom HTML to the page head for an editing procedure. Look up the three HTML hooks, custom CSS file and insertion order in Custom hooks reference. Built-in GoatCounter and Google Analytics have separate setup guides; adding their scripts a second time can duplicate counts.

…add favicons?

A. Domain-root icon

Place favicon.ico at your domain root for browsers that request it automatically. For a GitHub Pages project site under a path such as /repository, add an explicit icon link using the method below.

B. Explicit icon links

  1. Go to https://realfavicongenerator.net/ and follow the instructions.
  2. Configure the generated icon URLs to match their final location, including baseurl for a project site.
  3. In your repo, copy the HTML code into _includes/custom/custom_head.html.
  4. Also, download the icon package and host it on your repo on ./assets/favicon/.
  5. Build the site and check that the generated icon URLs resolve.

...use Chulapa font on my theme?

You can use Chulapa as a font just as you would do for any other font, since it is already installed. On your _config.yml:

chulapa-skin:
  vars  :
    headings-font-family: "chulapa, sans-serif"

This enables the font for headings. Without discretionary ligatures, the text appears as Chulapa.

To enable its distinctive ligatures, add these rules to assets/css/custom.scss:

h1,h2,h3,h4,h5,h6 {
    -webkit-font-feature-settings: "liga", "dlig";
    -moz-font-feature-settings: "liga=1, dlig=1";
    -moz-font-feature-settings: "liga", "dlig";
    -ms-font-feature-settings: "liga", "dlig";
    -o-font-feature-settings: "liga", "dlig";
    font-feature-settings: "liga", "dlig";
    text-rendering: optimizeLegibility;
}

Then your headings would display as Chulapa!

The documentation uses the chulapa CSS class to apply the font and its ligatures. For an inline name, use <span class="chulapa">Chulapa</span>. Apply the class to a paragraph to style its entire text:

Cool! I would like to use it. I love Madrid indeed! There is nothing quite like a relaxing cup of café con leche in Plaza Mayor or a romantic dinner in El Madrid de los Austrias, the oldest part of Madrid.
{: .chulapa}

…have a quick preview of a page of my site with any skin?

Open the skin previews to compare designs. To try one on your own site, change chulapa-skin.skin in _config.yml, save and publish. Follow Choose a design. Changing a preview on this documentation site does not change your own site.

…find an error in my _config.yml file?

Follow Fix a YAML configuration error. It covers locating the failing edit, checking indentation/quotes/duplicate sections and rebuilding. Valid YAML alone does not establish valid skin names, provider IDs or field locations.

…know which version of the theme I am using?

For a remote theme, check remote_theme in _config.yml. A suffix such as @v2.1.0 pins a release; an unpinned value uses the repository default branch and does not identify a fixed version. For a gem-based theme, check the chulapa-jekyll version in Gemfile.lock.

For pages using the theme’s head include, view the HTML source and look for this comment near the beginning:


<!-- Chulapa Jekyll Theme - VERSION NUMBER HERE -->

The HTML comment is a theme version marker. It does not identify the exact commit of an unpinned remote theme or any local overrides. Use a pinned tag or Gemfile.lock to identify the selected release.

…use jekyll-feed instead of Chulapa’s feeds?

Chulapa generates /atom.xml and /rss.xml. A document appears in these feeds only when include_on_feed: true and a date are set. To include all posts, add this default to your _config.yml, preserving your other defaults:

defaults:
  - scope:
      path: ""
      type: posts
    values:
      include_on_feed: true

If you prefer jekyll-feed, its default /feed.xml can coexist with Chulapa’s feeds.

Changing its path to /atom.xml without removing Chulapa’s Atom feed creates two pages with the same output path.

For most sites, keep the built-in feeds and link to /atom.xml or /rss.xml from your footer. If you need jekyll-feed, follow its setup guide and keep its separate /feed.xml address to avoid conflicting with the theme’s feeds.
