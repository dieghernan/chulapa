# Documentation and community evaluation

## Method

Live questions go to the same `/api/chat` endpoint used by the widget. Each
request is independent. This evaluates and improves the supplied context; it
does not train model weights. The runner sends four questions per 75-second
batch, retains complete answers and records response status and latency.
Human review checks factual accuracy, coverage of every requested part,
actionable settings/code and appropriate sources. HTTP 200 is not a quality score.

The baseline contains 48 questions covering installation, configuration, search,
comments, theming, layouts, snippets, FAQ, Markdown and variable/highlighting
references. Additional cases cover SEO and navigation plus five community
questions. Case files contain the expected checks and source references.

## Baseline findings

Basic local-video embedding, TOC settings, favicons, custom includes, skin
variables and highlighting previews generally produced usable answers.
Significant gaps or errors included:

- Missing gem update commands, translated dates, publisher settings, GA4 and
  Font Awesome kit precedence.
- Invented `child_list` instead of `child` in navbar YAML and missing dual style.
- Missing Algolia key fields and search attribution/deprecated options.
- A footer email example wrongly included `mailto:` in the URL field.
- Missing custom skin/Codeply guidance and filename sorting for galleries.
- Missing YouTube preview resolution and invalid duration example (`10:00`).
- Confusion between Markdown content TOC and theme navigation TOC.
- A privacy answer suggested robots.txt or sitemap removal as access protection.

The context additions target these gaps. The prompt asks for all requested
parts, omits unrelated options and limits default skin listings to examples
plus the catalog. Existing model, 450 completion-token allowance and concise
answer target remain unchanged.

## Context budget

The initial reviewed context was about 2,708 words / 21,326 characters. The
selective expansion is 3,876 words / 30,027 characters, rather
than copying complete documentation pages. It retains original source links.
Input allowance grows; output allowance does not. Live requests consume the
account's Workers AI allowance.

## Revised observations

The second round repeats 18 baseline cases and adds 13 SEO, navigation and
community cases. It fixes the missing plugin/update instructions, translated
dates, GA4, kit precedence, navbar child YAML, Algolia keys, footer email,
Codeply, YouTube resolution, filename sorting and privacy guidance. New SEO
cases distinguish canonical metadata from redirects, separate title fields,
explain Open Graph locales and avoid promising automatic image cropping.

Seven cases needed another targeted correction: publisher/author separation,
SCSS versus YAML placement, ISO 8601 duration, content TOC line breaks,
article random panels versus gallery parameters, complete Markdown link
syntax and complete feed defaults YAML. Explicit short examples were added,
then these seven cases were repeated against the final deployment.
All seven final answers corrected the specific errors being checked: complete
feed YAML and Markdown links, separate SCSS/config files, valid PT5M duration,
two-line content TOC, independent publisher/authors and show_random control.

The evaluation totals 61 distinct questions and 86 live requests including
repeats. All requests returned HTTP 200; this is transport evidence, not an
assertion that all answers are perfect. The 17 local automated tests pass.

Source precision remains a limitation: the feed answer in the revised round
invented an anchor despite the prompt requiring exact source URLs. Other
answers used a neighboring documentation section. Keep checking sources and
multi-part completeness; adding more input alone does not guarantee either.

## Limits

These are sampled live outputs, not a guarantee for every phrasing. Questions
remain independent, and no RSS/page retrieval is added. Multi-part requests may
still omit details, cite a neighboring section or include unnecessary prose.
Keep failing examples as regression cases and rerun affected batches when docs
change, rather than continually appending the full documentation.
